# Ноды и группы

Требования — `spec.md`, FR-5, FR-6, FR-7.

## Реестр нод (FR-6) — реализовано ядро

`wled00/lightmusic_node_registry.h` — header-only модель без зависимостей от Arduino, покрыта host-тестом `test/lightmusic/node_registry_test.cpp`.

Запись:

```text
MAC (6 байт) → name (≤32) → groupMask (≠0) → capabilities → lastSeenMs → configRevision
```

Правила:

- максимум **8** нод (`kLightmusicMaxNodes`);
- MAC — стабильный идентификатор, `upsert()` по одному MAC всегда возвращает ту же запись (дубликатов нет), при заполненном реестре — `-1`;
- новая нода получает имя `Node-XXYYZZ` (последние три байта MAC) и группу 1;
- `rename()` отвергает пустое имя и обрезает длинное до 32 символов;
- `setGroups()` отвергает нулевую маску; нода может состоять в нескольких группах;
- `remove()` освобождает слот.

Реестр **намеренно не подключён** к сети и UI: он не должен меняться от произвольного UDP-broadcast. Подключение произойдёт вместе с pairing (FR-7).

## Группы (FR-5)

8 групп, битовая маска. На master `syncGroups` задаёт адресатов пакета, на ноде `receiveGroups` — прослушиваемые группы. До реализации pairing источником истины остаётся локальная настройка `receiveGroups` на ноде.

## Pairing / provisioning (FR-7) — план

1. Нода анонсирует себя (кандидат: штатные sysinfo-пакеты WLED на порт 65506, которые уже содержат MAC, имя, тип платы и версию — master может собирать `lastSeen` пассивно).
2. Master показывает устройство как unpaired; пользователь включает pairing mode и подтверждает.
3. Пользователь назначает имя и группы; master отправляет revisioned-конфигурацию, нода подтверждает revision.
